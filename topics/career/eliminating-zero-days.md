# Eliminating zero days

A busy day can pass without progress toward a long-term goal. Messages, small requests, and meetings can leave little time for learning or improving a system.

Here, a "zero day" means a day with no progress on a chosen goal. Preparing a small next step makes it easier to get started when time is available.

## Break the goal into small steps

A goal such as "learn Linux I/O" is too broad for a short break between tasks. Choose a smaller step:

| Goal                                | Small next step                         |
| ----------------------------------- | --------------------------------------- |
| Learn Linux I/O                     | Trace the main steps of one system call |
| Improve deployment reliability      | Reproduce one deployment failure        |
| Understand the service architecture | Draw the path of one request            |

```text
Understand the service architecture
                |
        Trace one request
                |
          Draw its path
                |
Explain what each service does
```

Write down the next step in advance. When time is available, there is less to decide before starting.

## Save ideas as they come up

Routine work can reveal useful improvements. Write down the ideas while the details are fresh:

> The same configuration mistake caused two failed deployments. Add a check that detects it before rollout.

Keep these ideas in a short list. When time is available, choose one that fits. Some ideas may need to be broken into smaller steps first.

## Notice what changed

Progress can mean learning something, making a tool, or removing a blocker:

- **Learn something:** explain how a write reaches disk.
- **Build something useful:** write a small configuration checker.
- **Test an idea:** rule out a suspected cause of a failure.
- **Unblock work:** get a decision needed to continue a migration.

A few minutes may be enough to write one clear question or save a useful observation. Larger tasks still need longer blocks of time.

## Allow for busy days

Maintenance, helping a teammate, and handling an incident are useful work too. They may take the whole day. Leave time for rest as well.

If a goal keeps getting postponed, make the next step smaller or set aside time for it. The aim is to make progress easier to start.
