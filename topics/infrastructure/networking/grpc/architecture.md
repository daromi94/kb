# Architecture

End-to-end component stack for a gRPC call, from client business
logic down through the transport and back up to the server
implementation.

```
+----------------------------------------------------+
|  CLIENT                                            |
|                                                    |
|  Business Logic                                    |
|        |                                           |
|        v  local call                               |
|  +----------------+                                |
|  | Generated Stub |  marshal / unmarshal           |
|  +----------------+                                |
|        |                                           |
|        v                                           |
|  +----------------------------------------------+  |
|  | Channel                                      |  |
|  |  Interceptors -> Name Resolver               |  |
|  |                       |                      |  |
|  |                       v                      |  |
|  |                  Load Balancer               |  |
|  |                       |                      |  |
|  |                       v                      |  |
|  |                  Subchannels                 |  |
|  +----------------------------------------------+  |
|        |                                           |
+--------|--------- HTTP/2 / TCP --------------------+
         |
+--------|--------- HTTP/2 / TCP --------------------+
|        |                                           |
|  +----------------------------------------------+  |
|  | Server Runtime                               |  |
|  |  HTTP/2 Server -> Interceptors               |  |
|  +----------------------------------------------+  |
|        |                                           |
|        v  unmarshal / marshal                      |
|  +----------------+                                |
|  | Generated Base |  method dispatch               |
|  +----------------+                                |
|        |                                           |
|        v                                           |
|  Business Logic (Service Impl)                     |
|                                                    |
|  SERVER                                            |
+----------------------------------------------------+
```

**Client stub:** Generated by `protoc`. Presents a local interface
that mirrors the remote service. Marshals request objects into
Protobuf and unmarshals responses.

**Channel:** Long-lived object managing all network concerns —
interceptors, name resolution, load balancing, and subchannels
(logical abstractions that each manage an HTTP/2 connection to one
resolved backend).

**Transport:** A single TCP connection multiplexes many concurrent
RPCs, each mapped to one HTTP/2 stream.

**Server runtime:** Accepts HTTP/2 connections, decodes frames, and
runs server-side interceptors.

**Generated base class:** Routes incoming calls by HTTP/2 path,
unmarshals Protobuf payloads, and dispatches to the concrete service
implementation.
