# Auxiliary problems

A secondary problem solved not for its own sake but because its
methods, results, or insights illuminate the path to the original
goal. The connection between the auxiliary and primary problem must
remain intact — the effort is wasted if the auxiliary problem is
too detached.

## Forms

**Equivalent problems.** Rephrase the condition or transform the
data into a different format.

**Chain of problems.** Solve a sequence of sub-problems where each
output unlocks the next.

**Simplified problems.** Drop a challenging constraint to see how
the core system behaves in an ideal state.

## Application questions

- Is there a related problem that has already been solved?
- Can the problem be translated into a different domain where
  standard algorithms apply?
- If a specific constraint is temporarily ignored, does the path
  to the solution become clear?
